# RC158 — Manual Docker image gate and required Chromium prerequisites

Run 41737243981 (`workflow_dispatch`, RC157 commit `a1155ac`) failed in step 93, `Real Chromium JPG background and Logo upload/persistence acceptance`, with `ModuleNotFoundError: No module named 'playwright'`. The optional `Chromium editor UI acceptance` step was not selected in this manual dispatch, so it did not install Playwright. The **mandatory** JPG/Logo step remained unconditional, causing `validate` to fail before `image-build` (the Docker build job) could start. Node backend 582/582, frontend 251/251 and npm TypeScript/Vite compilation had passed. This is **not** a Dockerfile build failure.

RC158 adds an independent, mandatory browser preflight immediately before the JPG/Logo acceptance: when Python Playwright is missing it installs the pinned major range; when a tested browser path has not been exported it executes the existing Chromium bootstrap smoke and exports the resulting path for following steps. The JPG/Logo acceptance itself is NOT disabled or bypassed. An early source-contract test asserts that this bootstrap precedes the mandatory browser test, independently of optional flags, and that manual Docker publication remains opt-in and downstream of both `validate` and `image-build`. The RC157 manifest remains historical.

**Operator procedure:** in GitHub Actions > Quorivio CI and Docker Hub > Run workflow, choose main. Keep `publish_image=false` for a local image build/scan without Docker Hub publication. Set `publish_image=true` only when explicitly publishing, with compatible production environment approval, Docker Hub credentials and successful image scan. Use `browser_test=true` for extra Chromium UI acceptance, not to satisfy dependencies of a mandatory stage. Do not enable `rc_strict` until external RC criteria are met. No real 500-participant production trial or operator sign-off is implied.

**Release status:** 0.1.0-dev RC158, certified completion 85.25% (43 accepted, 17 partial); `rc_strict=false`, `publish_image=false`, `publish_latest=false` by default. Full GitHub CI, image build and real end-to-end load testing remain pending.
