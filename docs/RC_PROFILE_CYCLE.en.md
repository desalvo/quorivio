- **Functional fix:** the audience presenter-profile widget previously rendered `/api/auth/profile/photo/:id`, an authenticated private endpoint, so anonymous participants could not see presenters' photos. The public `/api/join/:code/presenter-profiles` endpoint now emits only `id`, `name`, and an appropriately encoded, session-scoped `photo_url` pointing at the existing public session presenter-photo endpoint. No private authenticated photo URL or user database fields are returned. Cache-Control no-store retained.
- **Unified profile save:** nickname and presenter display name are now validated and saved in one PostgreSQL transaction with a per-user row lock, a single UPDATE, primary-admin nickname protection, and unique-nickname conflict handling. A failed validation/uniqueness check cannot partially save one field. Legacy `/api/auth/profile` nickname-only updates and `/api/presenters/me/profile` name-only updates remain compatible.
- **Concurrency fix:** legacy presenter name-only PATCH no longer reads and rewrites a potentially stale `profile_photo_url`, preventing an unrelated name update from undoing a concurrent photo upload/delete.
- **Frontend UX:** presenter profile automatically loads on entering the page, offers one `Salva profilo` button instead of separate nickname/name saves and a manual load button, and keeps image upload/delete as explicit separate actions. Public widget consumes `photo_url`, not the private photo URL.
