# HAProxy Technologies real ingress CI — RC cycle 36

Run the **manual** `Quorivio CI and Docker Hub` workflow with `kubernetes_haproxy_test=true`, `publish_image=false` and `rc_strict=false`. The job creates a disposable 3-node KIND cluster (control plane + two workers), builds a local Quorivio image (no push), deploys the official HAProxy Technologies chart 1.54.3 from OCI into `quorivio-ci-haproxy`, and exercises the generated HAProxy ingress with a real HTTP client from inside each app pod. PostgreSQL 18, cross-worker placement, CI-only shared bind, unknown-host rejection, failover and post-replacement file availability are mandatory. The job has no real cluster credentials. Failure diagnostics contain resource statuses, not Secrets, container logs, user files or private responses.

**Not certified:** chart and runtime need the actual GitHub run; no local Helm/KIND available. CI shared Docker-host bind is not NFS/CSI RWX, a physically independent machine, production TLS, HAProxy Community controller, or operator SLA signoff. Do not increase the formal RC score until a successful run with exact SHA and unambiguous passing statements exists; do not claim that this proves production HA.
