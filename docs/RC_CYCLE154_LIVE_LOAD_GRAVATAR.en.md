# RC154 — Real 500-user rehearsal, per-account Gravatar and administration

## Changes

- The private, automatically provisioned `load-500-v1` demonstration has visible `participant-count`, two independent question widgets, rating 0–9, reactions and results controls. It remains unpublished until explicitly started, and the existing reset-to-ready operation clears accumulated test answers and rotates the join code. After deleting the demonstration, the normal account provisioning workflow recreates a clean copy.
- `tools/live_500_answers.py` is included in the Git repository and cumulative ZIP. The explicitly authorized CLI can reset and start the dedicated poll, create 500 synthetic participants, hold WebSockets open, observe the connected counter via the presenter channel and compare confirmed widget answers with the server aggregate. It refuses non-loopback HTTP, requires exact hostname confirmation, respects default request rates and emits an aggregate report without participant identifiers or credentials. A mock HTTP/WebSocket end-to-end test validates both counts and fail-closed discrepancies. Never run against an unapproved public service.
- Gravatar is **opt-in for each account** and off by default. Users may use the external Gravatar website to add/update an avatar and enable automatic import in Quorivio Profile. On successful authentication the API checks the fixed HTTPS SHA-256 email hash endpoint, compares the content checksum and reimports changed photos into the private local storage after image and ClamAV inspection. Manual profile uploads override the Gravatar setting. Unavailable Gravatar does not block login. Old copies are queued for deletion. Updating a Gravatar *at gravatar.com* remains an external website action; no Gravatar OAuth publishing credential is collected by Quorivio.
- Administration guides in Italian and English include an explicit operator procedure for starting, monitoring, resetting, and repeating the real load test, as well as Gravatar consent and privacy guidance.

## Validation and limitations

The local mock server test covers 500 widget answers and a smaller simultaneous-WebSocket presenter observation; no real production server was loaded. The complete TypeScript build, authenticated Chromium editor/PostgreSQL acceptance and true 500 concurrent sockets still require GitHub CI and a scheduled authorized server test. Baseline completion remains **85.25%** (43 accepted / 17 partial). `rc_strict=false`, `publish_image=false`, `publish_latest=false`. No commit, push, deployment or release by the assistant.
