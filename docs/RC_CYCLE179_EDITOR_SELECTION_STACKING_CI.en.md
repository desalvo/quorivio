# Quorivio 0.1.0-dev — RC179: Real editor contextual pointer above wrapped palette

**CI evidence:** GitHub Actions run [41878608401](https://github.com/desalvo/quorivio/actions/runs/41878608401), job `126744879605`, commit `88d0cbb842b131a5315e92a093e7c2e60349424b`, failed on 4 November 2026 in `Chromium editor UI acceptance (opt-in)`. Earlier steps including reproducible npm installation, unit tests, frontend/backend compilation and initial Chromium assertions completed successfully; no claim is made that the remaining integrated acceptance steps ran. The separate RC campaign summary failed as a consequence. ClamAV acceptance passed.

**Exact failure:** `tools/ci_browser_editor.py:272` attempted `click_canvas_tool(page, 'Duplica selezione')`, which called `control.click()` in `tools/ci_editor_context_tools.py:102`. Playwright's native pointer was blocked for 12 seconds by `.editor-widget-grid` / `.editor-icon-tool` from the `editor-widget-rail`; the button was visible and enabled but physically covered. A screenshot is available in the failed CI run's `chromium-editor-failure` artifact.

**Root cause:** RC178 correctly enlarged the wrapped insertion palette. However, the palette owns its own grid-row stacking context with `z-index:13` while the `.editor-stage` remains `z-index:1`. The fixed-position contextual toolbar has a higher *child* z-index but cannot escape the editor stage's lower stacking context. Its top controls are therefore rendered beneath the wrapped palette. This is a real pointer-accessibility defect, not a flaky timeout or obsolete string assertion.

**RC179 runtime change:** CSS raises `.editor-stage` to `z-index:70` **only** when it contains `.canvas-editor-group[data-tools-open="true"]` via `:has(...)`. The editor header remains above this stage and when tools close, the normal rail stays accessible. Selection, duplication and alignment stay native clickable; there are no forced clicks, pointer-event bypasses or changes to the underlying widget data model.

**Regression protections:** A Chromium fixture loads the shipped `style.css` and replays native `Duplica selezione` and alignment button clicks at 1440×900, 960×800 and 390×844. It checks `document.elementFromPoint` for physical hit ownership, verifies handler delivery, then confirms the palette is usable again after closing tools. The test was **red before** the CSS fix (hit owner `palette` at 1440px) and **green after**. A Python structural preflight is part of the early CI and the Chromium acceptance test runs immediately before `ci_browser_editor.py`.
