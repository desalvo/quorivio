## Completed software changes in this cycle (do not imply RC acceptance)

1. **Portable media IDs and duplication.** The original `.quorivio` importer reused exported session asset UUIDs, colliding with the source session's globally unique asset primary keys on repeated imports. `remapPortableAssets` now assigns independent fresh UUIDs per import and rewrites all relevant session theme/page/result backgrounds and image/logo/video/PDF widget references consistently, without mutating the input. The internal session duplicate endpoint now copies all referenced binary assets and metadata into its fresh draft, rejects missing source assets and preserves shared references. Both paths preserve ownership checks and do not clone submissions, participants, credentials or participation data. Asset content is rechecked (size, SHA-256, MIME signature) and the configured fail-closed antivirus policy applies to copied files. Transaction rollback removes staged new-session files on failure.
2. **Email MFA activation.** Password plus configured SMTP starts a **pending** 10-minute six-digit email challenge, stored separately from login challenges in `email_mfa_enrollments`. The factor is enabled only following successful code verification under a PostgreSQL row lock. Five incorrect codes exhaust a challenge. Issuance is limited to three requests per user per minute through shared `api_rate_windows`. Activating or disabling invalidates the user's earlier login sessions; TOTP is independent and remains untouched. UI now provides explicit request/confirmation actions and a six-digit OTP field. Password reset and TOTP flows remain separate. This fixes unverified email MFA enablement but **real SMTP enrollment and recovery are not E2E tested**.
3. **Administrative consistency.** Server setting patches now validate the **whole** proposed URL/retention/size combination before writing and save multiple settings in a single transaction. Public URL runtime state is updated only after commit. Profile photo updates/deletions use `SELECT ... FOR UPDATE` on the user row, preventing concurrent stale replacements; private old files are cleaned up on replace/delete, failed uploads do not leak an unowned file, and only server-minted photo paths may be removed.
4. **CI E2E coverage and manuals.** Added `tools/ci_portable_http.py` and wired it into PostgreSQL 18 CI startup. It exercises fresh admin sign-in, password change, rejected atomic multi-setting patch, private profile photo lifecycle, media upload, export/import `.quorivio` **twice**, fresh media UUIDs, internal duplication, shared image/background references, file integrity and tampered ZIP rejection. This CI step is newly introduced and has NOT run in GitHub Actions. Rebuilt six Italian/English role-specific PDF manuals from the existing design and cover, refreshed MFA, portability and admin operations, and synced public copies.
