## What this closes technically

Earlier RC295–RC297 tests verified percentage formatting, geometry and accessible roles with isolated CSS/DOM fixtures. Those tests did **not** prove that a real saved Quorivio session renders the same data and accessibility semantics.

RC298 adds an **always-on, mandatory** Chromium/PostgreSQL end-to-end acceptance against the *actual compiled frontend and authenticated disposable API*, without request interception or fake browser DOM. It creates two independent sessions using the real PostgreSQL persistence layer, with a source question whose `resultsView=pie` drives the linked result widget, and verifies the saved source/options/percent-settings after a readback.

The real browser acceptance then checks:

1. The desktop editor actually renders the pie with configured radius and a screen-reader-visible text list of all source options, real generated counts and exactly matching percentages. The invisible desktop list must occupy only a clipped one-pixel box, not shift the visible result layout.
2. Toggling the **actual editor Smartphone switch** makes the same list visually readable and non-overflowing; toggling back keeps desktop accessibility.
3. Opening the **actual presenter rehearsal** retains the linked pie, while switching to the participant rehearsal does not expose presenter-only aggregate result widgets.
4. A separate persisted, percentage-disabled session has no percentage legend, a neutral SVG accessibility label, and no percentages in the SVG path tooltips.
5. There are no browser JavaScript page errors; the external origin is explicitly restricted to disposable localhost HTTP, and test credentials are generated by CI.

The result counts inside the *rehearsal* are simulated by the application intentionally. The persisted source, chart settings and editor rendering are genuine; no simulated count is represented as a live participant vote.

## Remaining independent gate sign-offs

**A4** (real assistive technologies) and **B3** (real participant result visualization) remain **partial**, even after a successful RC298 run. To close them, an independent reviewer must test representative presentation and audience workflows using physical desktop/mobile devices with NVDA, VoiceOver and TalkBack, verify focus/order and announced options/counts/percentages, record successful and denied participant flows, and attach redacted evidence to the off-repository packet. Use `tools/rc_external_evidence.py --attach ... --gate A4 --facet nvda|voiceover|talkback|keyboard-audit` and corresponding `B3` facets `physical-results` and `screenreader-results`. Independent sign-off and source SHA matching are still mandatory; CI cannot replace these reviews.

Do not store real participant identities, tokens or unredacted reports in public Git or CI artifacts. See `docs/RC136_EXTERNAL_ACCEPTANCE_EN.md`.
