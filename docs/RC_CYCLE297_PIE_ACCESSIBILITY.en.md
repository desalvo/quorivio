# RC297 — accessible pie-result percentages and hidden-percentage semantics

**Baseline:** RC296 merged in main at `ad1fefb326d0afab7633b4f8f481caf56b572cbd`; mandatory CI [42822090385](https://github.com/desalvo/quorivio/actions/runs/42822090385) succeeded.

## Functional correction

RC296 deliberately hid the compact phone percentage key on wide desktop windows using CSS `display:none`. Although the desktop SVG displayed percentages visually, the accompanying source-option labels and counts were not available as a reliable text list to screen-reader users.

RC297 keeps the source/percentage key in the accessibility tree on **desktop** with a clipped, absolutely positioned one-pixel layout. It is out of the visual flow and does not move the chart or result rows. The exact same key becomes a regular visible grid on narrow windows and authored smartphone editor, rehearsal and audience views.

Every nonzero slice has an accessible list-item name containing the actual answer label, the vote count with Italian singular/plural, and the exact percentage generated by the same shared formatter as the SVG and visible phone legend. Color swatches remain decorative; percentage labels never depend on color recognition. When `pieShowPercentages` is disabled, the key is absent and the SVG accessibility name, title, and slice tooltip no longer claim to reveal percentages.

The original desktop SVG callout leaders, editable pie radius, source question formatting, R answer-key toggle and live-result privacy rules remain unchanged.

## Mandatory automated evidence

- Early Node assertions guard the source mapping, hidden-preference behavior, clipped desktop key, and mobile CSS restoration.
- Chromium/Playwright checks the actual accessibility-role query (list and listitem names) for desktop, 360/390px mobile widths, authored editor-phone and audience-phone preview. A separate disabled-percentage check verifies the absence of the key.
- Desktop Chromium tests measure result-row rectangles before and after removing the offscreen key and assert no geometric movement; the existing RC296 phone-geometry suite is updated to distinguish actual visual visibility from mere `display:grid`.
- Both suites run in the standard **mandatory** production-quality GitHub Actions job. This new PR must still pass its associated build, tests and inventory verification.
